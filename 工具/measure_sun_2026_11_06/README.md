## 3. 质心算法与哨兵分支
- 质心取「该最大连通块所辖降采样格覆盖范围内、全部原始过阈像素（>=250、上半区内）坐标均值」，**不是**降采样格中心均值。理由：格中心均值带 4px 网格量化吸附，偏差可达 ±2px；台账旧读数按像素级口径手算，须同精度对话。该分歧有专门单测钉住（`test_centroid_is_original_pixel_mean_not_cell_center_mean`，夹具为偏心椭圆盘，实测两口径取整读数 190,55 vs 191,56 确实分歧）。
- bbox＝组件内原始过阈像素 min/max 还原回原分辨率，右/下缘开区间（max+1）。
- 面积 area_px 仍取格口径 ×16（与 sun_blob 对拍的量，口径不许改）。
- 哨兵：上半区无任何 >=250 像素时返回
  `{"cx_px": None, "cy_px": None, "cx_ratio": None, "cy_ratio": None, "area_px": 0, "bbox": null, "w": 实际宽, "h": 实际高}`；
  位置字段全 None、绝不返回 (0,0)（0,0 是合法左上角，会被误读成「日面在左上」）。
  另一边界：过阈像素全部落在残行/残列（被口径③丢弃、连历史脚本也计 0 的带）时同样走哨兵。

## 5. 与旧手算读数的对比与差异归因（如实：三枚全部对不上）

| 图 | 旧台账手算 | 本工具（交付口径 L>=250/上半区/×16 最大块） | 一致性 |
|---|---|---|---|
| D03 v04 | x=273/1792=0.15W、y=386、簇 2745 px | x=237=0.13W、y=470、簇 1904 px | 方向一致（左带），数值不一致 |
| L008 00格 | x=191/1440=0.13W、y=253、簇 1306 px | x=183、y=362、簇 336 px | x 接近，y/面积不一致 |
| L007 00格 | x=484/960=0.50W、y=680 | **哨兵（无检出）**，area_px=0 | 完全不可复现 |

差异归因探针（本轮实测，非推测）：
- 阈值层面：三枚图在上半区的 L 灰度峰值分别只有 253 / 254 / **249**。L007 上半区灰度最大值 249 < 250，即**交付口径下该格根本不产生任何极亮簇**——`sun_blob` 对同一文件直调也返回 0，说明旧读数「00格极亮簇 x=484、y=680」从来不是按 ≥250 灰度口径算出来的（旧读数的 RGB 通道 max 到得了 255，L 灰度被 0.299/0.587/0.114 衰减拉低）。
- 把阈值降到 245（本轮探针实测）：L007 原始像素级最大簇质心 = (484, 683)，与旧读数 (484, 680) 几乎逐轴吻合 → 旧读数极可能是肉眼/最低灰度点式口径，或等效 ~245 阈值。
- D03 旧读数窗口 (273±30, 386±30) 内 L>=250 像素数实测 **0**（窗内灰度峰值仅 221）；该图上半区 >=250 的左带其实是两枚簇（1904@≈(237,470) 与 1280@≈(246,318)），旧读数 2745 落在两者之间、位置 (273,386) 恰是两簇中点一带——旧手算疑似把日盘+辉光带整体目测成了一步读数。
- L008 同理：旧读数窗 (191,253) 内 L>=250 像素实测 0（窗内峰值 247）；245 阈值下该附近有 1808@(170,286) 与 1296@(130,226) 两簇，与旧「1306 像素」量级相当，但交付口径下左上日盘不过阈、最大簇反而是 y=362 一带的 336 px 窄带。
- 结论（要申报的发现，不为对数字而调阈值）：**上一轮台账的日面读数与已交付测量口径（≥250 灰度）不同源，三枚均无法机器复现**；其中 L007 在交付口径下直接零检出。重出阶段的 C99 判据若要沿用旧台账数字作对照，必须先统一口径；本工具严格站在交付口径一侧，并保留逐枚对拍守卫。
