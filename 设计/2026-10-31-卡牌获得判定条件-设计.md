# 卡牌获得判定条件 · 程序设计依据

> 状态：设计稿（2026-10-31，随卡牌体系五类总纲落定后建立）
> 目的：供后续编写系统程序时判断"某张卡片何时、在什么条件下可被角色获得"，作为判定规则的唯一口径。
> 上游：运行模拟确认稿主题1"五类卡牌总纲"、草案《钛湖城卡牌体系-细化草案-v01》、设计《2026-10-31-职业卡行业细分》《2026-10-31-现实权益兑换卡》《2026-10-31-成就卡打卡套系》
> 数据依赖：`数据/城市空间名录.json`（264地点）、`数据/产业就业源表.json`（20大类163小类）、技能标签库（398标签）、卡牌族目录（A1–A8 能力、B1–B4 学习、岗位 5151）、城市记忆（历史层）

---

## 〇、判定原理总览【先读】

所有卡牌的获得都走同一套「**事件 → 规则匹配 → 条件校验 → 发放/登记**」引擎，判定不依赖人工。

```
游戏内事件发生（签到/学习/训练/购买/制造/入职/晋升/打卡/达成…）
        │
        ▼
触发卡牌获得事件（event_type + 触发源 + 目标对象）
        │
        ▼
按卡牌类别路由到对应判定规则（第四~第九节）
        │
        ▼
条件校验（额度/前置/上限三关），见第三节
        │
        ▼
通过 → 发放卡片 + 结算积分 + (如属成就)登记城市记忆
不通过 → 丢弃并记日志（不重复触发）
```

**两类判定本质**：
- **判定式（真/假条件）**：是否满足获得条件 → 满足即发。
- **登记式（事实累计）**：达成事实记录后，由"累计值达标"触发（主要用于成就卡、打卡）。

**幂等原则**：同一张卡对同一角色**生命周期内只发放一次**；重复达成不重复发卡，但成就打卡可重复登记（打卡本身是事实记录，套系集齐章只盖一次）。

## 一、卡牌通用定义（五类底层契约）

任何一张卡必须满足，判定前先行校验：

| 字段 | 说明 | 校验 |
|---|---|---|
| card_type | 类别：capability / career / item / reward / achievement | 枚举，五选一 |
| card_id | 卡唯一编号 | 全局唯一，不重复 |
| owner_id | 持有人（账号 / 角色） | 归属明确，单持有人 |
| ledger_id | 所属账本（物品账本/卡的账本/成就目录等） | 必须落到某账本 |
| obtain_time | 获得时间戳 | 现实时间，供兑换周期计算 |

> 统一定义：所有卡"实体唯一、归属明确、有账本、无重复复制"。**任何卡都不允许凭空复制、不允许一本多花、不允许重复挂牌**。

---

## 二、持有上限统一闸门【任何发卡前必查】

判定通过后、实际发卡前，先过持有上限三关（五类共用同一上限规则）：

| 关卡 | 规则 | 判定动作 |
|---|---|---|
| ① 同族上限 | 同一卡族在手上**最多 2 张** | 计数 owner 名下同 card_family 的在手卡数 ≥2 → 拒发 |
| ② 总持有上限 | 角色同时持有卡牌总数**上限 12 张** | 计数 owner 在手总卡数 ≥12 → 拒发 |
| ③ 跨轮继承上限 | 转入下一轮的卡/积分**不超过 4 张** | 跨轮继承清单计数 >4 → 超限部分不发卡、不产生积分 |

**超限处理**：超限部分**不产生新增积分**（防刷分）；卡本身不发放，日志记录"因持有上限未发放"。

> 例外：成就卡只登记事实、跨轮保留记录，**不占卡牌继承名额**（见第九节）。**定稿（2026-11-01，原问句收口）**：成就卡
> 只登记不持卡，因此不占 ① 同族（2 张）② 总持有（12 张）③ 跨轮继承（4 张）三项上限——这三项数值登记在
> `数据/岗位准入正典.json` 的 `参数.持有上限`，且正典的 12 个 `CRD-` 卡牌族里本就不含成就族；
> 其积分仍照常结算，重复打卡由幂等条款拦下（见第十节第 5 步）。

---

## 三、条件校验三关（金标准）

所有发卡判定经过三层逐级校验，全过才可发放：

1. **额度关**（数值边界，防突破平衡）
   - 能力卡：五维微调单卡 ≤2 点；同维度累计 ≤4 点（跨多张叠加仍受限）；阶推进只推 1 阶，不得触及"权威"。
   - 职业卡：学习类只推标签阶，**禁止跳层**；资质只走培训+学习+事件，禁止工作途径；A01 整类仅背景在册不可申请、A08 无融资证券业务（C46）。
2. **前置关**（必须满足的前置条件）
   - 职业卡晋级高阶：LVL4/LVL5 必须 关键场景 + 经历（不能只靠训练卡）。
   - 兑换卡：积分达到门槛 + 兑换周期内未满频次。
3. **上限关**：见第二节。

## 四、能力卡判定（capability）

> 作用：改变五维（智力/情商/体力/韧性/执行力 **1—20 整数**，唯一口径＝`数据/运行参数正典.json` 的 `参数.技能.五维刻度`＝[1,20]，
> 与 C76、《运行参数包-design》§1 同口径；本文早期草稿写的「0–100」已于 2026-11-01 按正典更正），每张只绑定"提升五维"一种效果。
> 底层卡族：A1–A8。

**触发事件**：完成一次"学习 / 训练 / 实战 / 事件"动作。

**判定条件**（全部满足才发）：
1. 事件结果判定成功（训练完成度/学习课时达标等，由对应玩法子系统给出）。
2. 额度校验通过：
   - 该卡单卡微调 ≤2 点；
   - 目标维度当前累计（含本次）≤4 点；
   - 阶推进：本次至多推 1 阶，且推进后不触及"权威"；
   - 不得直接授予岗位/公司职位、不改月薪带/住所锚/合同金额、不得授予公职。
3. 上限闸门通过（同族≤2、总≤12）。

**发放动作**：登记该卡 → 维度数值按效果更新（受额度约束）→ 结算积分（1 分；微调达 2 点封顶再 +1）。

**数据来源**：角色五维当前值、事件结果记录、卡库目录。

---

## 五、职业卡判定（career）

> 作用：提升某一**行业**（A01–A20）的胜任能力与职业进阶。
> 粒度：**只到行业大类**，不细分岗位/公司。底层：岗位卡 5151 + 学习族 B1–B4 + 技能标签 398。

**触发事件**：完成"岗位实训 / 课程结业 / 证照培训 / 自学笔记 / 关键场景 / 经历认定 / 资质获得"。

**判定条件**（按效果类型分支）：

| 效果类型 | 判定条件 |
|---|---|
| 推进标签阶（S1/S2/通用阶） | 学习类卡牌达成 + 只推 1 阶 + 不跳层（见习→熟练→精通→权威逐阶） |
| 晋级高阶（LVL4/LVL5） | **必须** 关键场景 + 经历 达标，训练卡不满足 |
| 获得资质 | 只走 培训 + 学习卡 + 事件；**禁止工作途径**；该行业资质项未持有时才发 |
| 行业归属 | 小类归属以 `产业就业源表.json` 20 大类为准，卡侧不另立分类 |
| 禁项 | A01 整类不可申请（仅背景在册）；A08 无融资证券业务（C46） |

**配套硬约束**：
- 同一张职业卡对同一行业对角色只发一次（不可重复拿同行业卡刷阶）。
- 上限闸门通过后才发。
- 职业卡本身**不跨轮**：靠再就业重启，不进入跨轮继承清单。

**发放动作**：登记行业职业卡 → 更新该行业标签阶 → 结算积分（2 分；晋级 1 阶 +1；获资质 +2）。

## 六、物品卡判定（item）

> 作用：一切持有的实体资产一卡一物承载。
> 底层：物品卡牌账本（第34主题六类账本之一）。

**触发事件**：购买 / 制造 / 赠予 / 继承 / 出租登记 等资产变动。

**判定条件**：
1. 资产来源合法（有交易/制造/赠予/继承流水，挂到账本）。
2. 一物一卡、实体唯一：目标物品当前无在手的卡 → 才建卡；已有一卡不重复开卡。
3. 不得凭空复制、不得重复挂牌出售（衔接二手折价上限）。
4. 住宅非产权：仅"社区住所卡"登记使用权益，**不开放买卖过户**。
5. 上限闸门通过。

**发放动作**：物品账本新增一条（归属/位置/数量）→ 可能涉及跨轮继承（资产类卡跨轮继承；资金/账本跨轮清空重启）→ 结算积分（依稀有度 1–5 分，高价值更高）。

**数据来源**：交易流、制造单、赠予/继承记录、物品账本。

---

## 七、现实权益兑换卡判定（reward）⭐运营层

> 作用：账号层"积攒卡牌积分兑换现实奖品"。
> 强隔离：账号层机制；与现实货币、虚拟钛币（TT）三方隔离；不可充值/提现/买卖。

**积分入账判定**（随各卡发放自动结算，见各节"结算积分"）：
- 能力卡：基础 1，微调达 2 点 +1。
- 职业卡：基础 2，晋级 1 阶 +1，获资质 +2。
- 物品卡：依稀有度 1–5。
- 成就卡：3–10（按套系难度），集齐一套额外奖励。

**兑换判定**（发起兑换时校验）：
1. 当前账号积分 ≥ 该档门槛（T1=50 / T2=150 / T3=400 / T4=1000 / T5=2500）。
2. 该档位在**现实兑换周期**内未达上限（T1 每月 1 次 / T2 每季 1 次 / T3 每半年 1 次 / T4 每年 1 次 / T5 年度限量）。
3. T5 需人工审核通过。
4. 兑换**不改变**虚拟数值与游戏内经济。

**跨轮规则**：
- 积分随物品卡跨轮继承：虚拟轮次重置不清零积分池。
- 但仍受持有上限约束（同族2/总12/跨轮4）；超限部分不产生积分。
- 暂不设单账号积分池绝对封顶（"先不用"；后续如需防刷再补上限）。

**数据来源**：账号层积分池（独立于虚拟轮次）、兑换记录（历史层，不参与判定）。

## 八、成就卡·事件/达成系判定（achievement-event）

> 作用：记录经历过的关键事件与达成的目标；只登记事实，不改数值与判定。

**触发事件**：达成某关键事件（如完成晋升答辩、经历全城轮回）、达成某目标（如跑满 30 片区、集齐某职业卡族、自营店连续经营 10 年）。

**判定条件**：
1. 目标事件/目标的**事实记录**成立（由对应子系统确认达成时间与证据）。
2. 该成就此前未发放（幂等）：同一成就对同一账号只发一次。
3. 不设排名、不比拼；**不影响任何数值判定**。

**发放动作**：登记进成就目录 → 进城市记忆（跨轮保留记录）→ 结算套系积分。

**数据来源**：城市记忆（历史层）、事件日志、各子系统达成记录。

## 九、成就卡·地点打卡系判定（achievement-checkin）⭐核心可逐张判定

> 打卡对象：`城市空间名录.json` 264 地点（城市片区20 + 功能区40 + 标志建筑60 + 居民区120 + 产业小镇16 + 特色村落8）。
> 套系结构：**景群（60地标分约20线）/ 板块（20片区+功能区，沿环湖归环）/ 全域（终极巡礼）**。

### 9.1 单点打卡判定
**触发事件**：角色"抵达/到访"某地点（打卡签到动作）。

**判定条件**：
1. 目标地点 id 存在于地点名录（**L／D／F／R／S 五类前缀**：地标 60、片区 20、功能区 40、居民区 120、聚落 24，合计 264 条；
   名录里没有 U／T／C 前缀，早期草稿把交通与商业类目误列为编号族，2026-11-01 按 `数据/城市空间名录.json` 实测更正——漏掉 S 会让 24 个聚落的打卡必判非法）。
2. 打卡系统确认到访（有位置/签到证据）。
3. **幂等**：同一地点同一角色只记一次打卡（已打卡 → 重复打卡不重复记，不重复套系积分）。

**登记动作**：在打卡表登记 `(owner, location_id, first_checkin_time)` → 同时标记所属景群与所属板块环（同一地点可同属两类套系，打卡一次两套并记：主景群 + 板块环，各记一次归属）。

### 9.2 套系集齐判定（盖章）
每套集满发"套系完成章"（只盖一次）。**判定方式：集合包含**。

```
景群套系集齐 = 套系定义的地点集合 ⊆ 该角色已打卡地点集合
板块套系集齐 = 板块环内所辖片区/功能区全部已打卡
全域套系集齐 = 对应全域条件全部已打卡/已达成
```

**套系示例与奖励（积分结算）**：

| 层级 | 套系 | 集齐条件 | 套系积分 |
|---|---|---|---|
| 景群 | 钛湖八景 | L001–L008 全部打卡 | +8 |
| 景群 | 湖湾生活线 | L012+L016+L017+L018 | +4 |
| 景群 | 文教知识线 | L003+L004+L005+L046 | +4 |
| 景群 | 文体活力线 | L028+L029+L030+L047 | +4 |
| 景群 | 生态科普线 | L031+L032+L033+L059+L060 | +5 |
| 板块 | 中央湖岸环 | 主城各滨湖功能区全部打卡 | +8 |
| 板块 | 东岸文教科创环 | D02+D07+D09 等全部 | +6 |
| 板块 | 西岸文旅生态环 | D08+D19+D20 等全部 | +6 |
| 板块 | 南岸生活商贸环 | D06+D10+D16+D18 等全部 | +6 |
| 板块 | 北岸行政产业环 | D01+D13+D14 等全部 | +6 |
| 全域 | 全城地标巡礼 | 60 地标全部 | +60 |
| 全域 | 全城片区巡礼 | 20 片区全部 | +20 |
| 全域 | 外围聚落探访 | 16 产业小镇 + 8 特色村落 | +24 |
| 全域 | 湖水系环 | 湖/入境河/出境河沿线 | 按段 |
| 全域 | 城市记忆册 | 集齐城市记忆级事件成就 | 套系章 |

> 单点打卡本身发"打卡卡"（成就卡，3–10 分按套系难度）；套系集齐另发"套系完成章"与额外奖励。二者不重复计单点分。

## 十、判定时序与积分结算汇总

| 步骤 | 动作 | 前置/说明 |
|---|---|---|
| 1 | 事件发生并产生事实记录 | 由各玩法子系统 |
| 2 | 路由到卡类别判定规则 | 第四~九节 |
| 3 | 额度关 + 前置关校验 | 第三节 |
| 4 | 持有上限闸门 | 第二节（成就卡仅不占名额但照常登记） |
| 5 | 幂等检查 | 同一卡只发一次/同一打卡只记一次 |
| 6 | 发放卡片/登记成就 | 写入对应账本目录 |
| 7 | 结算积分 | 各节"结算积分"；集齐套系另加 |
| 8 | 积分入账号层池 | 兑换卡用；随物品卡跨轮继承 |

## 十一、数据模型建议（供程序建表）

**cards（卡实例表）**
`card_id, card_type, card_family, owner_id, obtain_time, source_event, is_carried_over(F)`

**card_catalog（卡目录/规则表）**
`card_id, effect_type, effect_value, family_limit, stat_affected(五维方向), industry_code(职业), rarity(稀有度1-5), base_score, bonus_score_rule`

**checkins（打卡表）**
`owner_id, location_id, first_checkin_time, scene_group_id, board_ring_id`

**collections（套系进度表）**
`owner_id, series_id, series_type(景群/板块/全域), collected_count, total_count, is_completed, completed_time`

**reward_points（账号层积分池，独立于虚拟轮次）**
`account_id, total_points, tier_used[T1..T5], last_claim_time[T1..T5]`

**memories（历史层/城市记忆）**
`record_id, owner_id, memory_type, content, time`（兑换/成就记录入此，不参与判定）

**cross_round（跨轮继承清单）**
`owner_id, carry_type, entity_id, count(≤4)`

## 十二、防刷与一致性约束

- **幂等**：所有发卡/打卡/盖章都先查重，重复触发不发、不重复计分。
- **积分防刷**：超持有上限部分不产生积分；同行业职业卡不可重复刷阶；兑换有周期上限。
- **隔离**：兑换积分不可充值/提现/买卖，只随玩法真实达成；与现实货币、钛币三方隔离，不构成充值/提现通道。
- **不在同一判定的权威外溢**：能力卡阶不触及权威、职业卡高阶必须经历+关键场景、资质禁止工作途径。
- **日志**：被拒发/超限/重复的记录进日志（不落卡），便于运营核查。
