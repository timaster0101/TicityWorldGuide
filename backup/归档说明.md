# 设定集 backup 归档目录 · 说明

> 创建：2026-11-06 · 裁定 C133（B 前置裁定）
> 用途：所有被替换淘汰的**老图 / 老视频**统一归档于此，与线上引用分离，仅作历史备份，不参与任何校验、编译、开图清单引用。

---

## 一、归档范围（哪些东西进 backup）

凡在 303 条 image_file 整批替换、或后续任意替换/淘汰流程中被换下的**图像、视频**资产：
- 被替换的 `数据/图集/四向/{ID}/*.jpg` 四向图
- `数据/图集/` 根目录历史散图（D01 系列、L007/L008 系列、入驻用户合照、全域鸟瞰图旧版等）
- `数据/图集/全城鸟瞰-四向-v01/` 旧版全城图
- 被替换的 `vibe_images/` 旧候选图
- 后续任何被淘汰的图片 / 视频 / 分镜片段 / 配乐成品等（用户 2026-11-06 拍板：**以后其他老图、老视频都挪这里归档**）

## 二、归档目录结构

backup 内按**原相对路径结构**镜像，保证"从哪来、回哪去"可追溯：

```
backup/
└─ 原目录相对路径/
   └─ 原文件名
```

例如 `数据/图集/四向/L001/四向00-主向-朝北-r01.jpg` → `backup/数据/图集/四向/L001/四向00-主向-朝北-r01.jpg`。

归档用**移动（move）**而非复制——被归档文件从原位置移除，原位置成为新图占位/待替换区。

## 三、与校验的关系

- `verify_image_assets.py` 扫描数据目录时明确跳过 `数据/图集`（`rel_dir == '数据/图集' or startswith('数据/图集/')`），故归档后**不会**因老图离开而产生校验误报。
- 但开图清单 `image_file` 字段若仍引用已归档路径，需在替换时同步更新为新图路径（见流程节）。

## 四、归档流程（替换时的标准动作）

1. 新图通过校验 → 把新图落到 `数据/图集/四向/{ID}/` 对应位置（原占位）
2. 把该 ID 的**老四向图**从原位置 move 到 `backup/数据/图集/四向/{ID}/`
3. 更新开图清单 `image_file` 字段 → 新图路径
4. 跑 `verify_image_assets.py` 全链校验自证
